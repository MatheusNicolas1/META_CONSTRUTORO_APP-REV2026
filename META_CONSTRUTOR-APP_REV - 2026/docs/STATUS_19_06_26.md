# STATUS 19/06/2026 — Erro fatal: `React.Children.only`

## Diagnóstico

### 1. Erro raiz na rota `/` (Home)

**Localização:** `src/components/PerformanceOptimizedApp.tsx`, linha 517

```tsx
<Route path="/" element={<><PublicThemeEffect /><Index /></>} />
```

**Problema:** O react-router-dom v6 (com flag `v7_startTransition: true` ativada na linha 503) usa `React.Children.only()` internamente no `Route` para garantir que `element` receba **exatamente um** filho React. Um fragmento `<></>` com **dois filhos** (`<PublicThemeEffect />` + `<Index />`) faz o `Children.only` lançar o erro.

**Flag ativada:**
```tsx
<BrowserRouter future={{ v7_startTransition: true, v7_relativeSplatPath: true }}>
```

**Mesmo padrão também ocorre nas rotas:**
- `/sobre` (linha 528)
- `/contato` (linha 529)
- `/preco` (linha 530)
- `/home2`, `/preco2`, `/blog2`, `/contato2`, `/sobre2` (linhas 532–536)
- `/blog`, `/blog/page/:num`, `/blog/:slug` (linhas 542–544)

Todas com `<><PublicThemeEffect /><SafeSuspense ...>...</></>` no `element`.

### 2. PostHog — 404s (não fatais, mas poluem o console)

**Domínios falhando:**
- `us-assets.i.posthog.com/.../config.js` → 404
- `us.i.posthog.com/...` → 404
- `bgdvlhttyjeuprrfxgun.supabase.co/.../analytics_events` → 401/403

**Causa:** O PostHog está configurado com `api_host: 'https://app.posthog.com'` (linha 7 do `analytics.ts`), mas o snippet JS carregado tenta conectar nos servidores `us.i.posthog.com` (US cloud). A chave `VITE_POSTHOG_KEY` parece ser de uma região/projeto que não existe mais, ou o host configurado não corresponde à região da chave.

**Além disso:** O envio de `analytics_events` para o Supabase falha (401/403), indicando que as permissões RLS da tabela `analytics_events` não permitem insert anônimo.

## Correções Necessárias

### 🔴 PRIORIDADE MÁXIMA — FIX do `React.Children.only` (desliga o site)

**Arquivo:** `src/components/PerformanceOptimizedApp.tsx`

**O que fazer:** Envolver os dois elementos em um único wrapper ao invés de usar fragmento com múltiplos filhos.

```tsx
// ❌ ANTES — quebra:
<Route path="/" element={<><PublicThemeEffect /><Index /></>} />

// ✅ DEPOIS — funciona (PublicThemeEffect dentro do Index ou wrapper):
<Route path="/" element={<Index />} />
```

**Opção 1 (recomendada):** Mover `PublicThemeEffect` para **dentro do componente `Index.tsx`**, já que ele é um efeito de tema que só faz sentido na landing page.

**Opção 2 (menos intrusiva):** Criar um wrapper que englobe ambos:

```tsx
const PublicPage = ({ children }: { children: React.ReactNode }) => (
  <><PublicThemeEffect />{children}</>
);

// Uso:
<Route path="/" element={<PublicPage><Index /></PublicPage>} />
```

**Opção 3 (rápida):** Colocar `PublicThemeEffect` dentro do próprio `Index.tsx` (antes do `<SEO>` ou antes do `<PublicNav>`).

> ✅ **Recomendação concreta:** Opção 1 — colocar `<PublicThemeEffect />` dentro de `Index.tsx`, e remover todos os fragmentos `<><PublicThemeEffect />...` das rotas.
